\doxysubsection{Detailed Description}
Implements multithreaded CAN communication for the K-\/\+Globe Elevator Service Controller. 

Provides the main CAN communication system used by the Service Controller. CAN messages are received in one thread, placed into a priority queue, and processed in a separate thread.

The implementation also communicates with the elevator database to process website requests, update floor and door information, control operating modes, log CAN traffic, and coordinate elevator audio announcements.

Processes CAN messages stored in the priority queue. 

Runs independently from the CAN receiver thread. The processor waits for queued CAN messages and determines the appropriate action based on each message\textquotesingle{}s CAN ID.

Supported message sources include:
\begin{DoxyItemize}
\item Supervisory Controller.
\item Elevator Controller.
\item Car Controller.
\item Floor 1 Controller.
\item Floor 2 Controller.
\item Floor 3 Controller.
\item Website car controller.
\item Website floor controllers.
\end{DoxyItemize}

Depending on the received message, this function can transmit a new CAN command, update the Elevator database, log CAN activity, update floor information, or play a floor audio announcement.

Receives CAN messages and monitors website elevator commands. 

Runs as the CAN receiver thread for the Service Controller. The function opens and initializes the PCAN device, publishes the shared CAN handle, receives physical CAN messages, and places valid messages into the priority queue.

The receiver also polls the Elevator database approximately every 250 milliseconds for:
\begin{DoxyItemize}
\item Operating mode changes.
\item Website floor requests.
\item Floor-\/controller requests.
\end{DoxyItemize}

Door-\/open and door-\/closed CAN messages are processed immediately and their status is written to the Elevator database.

Maintenance and Sabbath modes can pause normal physical CAN request processing and clear queued requests.
